# ЧМОК

**ЧМОК** — сюжетная настольная игра на двоих для домашнего свидания (18+). Это русская вольная адаптация формата [playsmooch.com](https://playsmooch.com/): кольцевое поле, три настроения, главы с сюжетом, задания трёх уровней смелости, две короны в финале.

🔗 **Играть:** <https://and7ey.github.io/chmok/>
🕹 **Режимы:** вчетвером… нет, ровно вдвоём — за одним экраном (hot-seat) или онлайн, каждый в своём браузере.

Всё статично и бесплатно: ни своего сервера, ни аккаунтов, ни базы данных, ни аналитики. Онлайн идёт **напрямую между двумя браузерами** через WebRTC.

## 1. Что это и как в это играть

Маршрут игрока:

```
/            лендинг: три настроения, поле, правила, FAQ
/rules       полные правила
/terms       пользовательское соглашение
/privacy     приватность
/play        игра: возрастной гейт → меню режима
```

В `/play` три двери:

| Режим | Что происходит |
| --- | --- |
| **Вдвоём за экраном** | Один редьюсер, ходите по очереди, имена вводятся на экране настройки. |
| **Создать комнату** | Вы — хост. Генерируется код из 4 символов и ссылка-приглашение, дальше лобби, настройка вечера и старт главы. |
| **Войти по ссылке или коду** | Вы — гость. Открываете ссылку, вставляете код, попадаете в партию, которую ведёт хост. |

Ссылка-приглашение выглядит так:

```
https://and7ey.github.io/chmok/#/play?room=K7MR&as=guest
```

Код комнаты — 4 символа из алфавита без `I/O/L` и цифр `0/1`, чтобы его можно было продиктовать голосом:

```
ABCDEFGHJKMNPQRSTUVWXYZ23456789
```

## 4. Правила: как устроена партия

### Поле

Кольцо 6×6 — **20 клеток** по периметру, индексы 0…19 по часовой стрелке:

- `0` — **«Свидание»** (старт),
- **17 улиц** (`Открыточный переулок` 80 … `Полуночный особняк` 320, шаг цены 15; в коде — `Space` с `kind: 'spot'`),
- `5` и `19` — **«Сюрприз»** (карты судьбы).

### Ход

```
awaiting-roll → moving → walking → { buy | resolve | fate | finishTurn }
```

1. Ходящий бросает два кубика (1d6 + 1d6).
2. Фишка идёт по кольцу; круг через «Свидание» даёт **+200**.
3. Приземление:
   - **свободная улица** → фаза `buy`: выкупить за цену или оставить свободной;
   - **чужая улица** → фаза `resolve`: ходящий тянет карту улицы и платит владельцу;
   - **своя улица** → бонус дома **+60**;
   - **«Сюрприз»** → фаза `fate`: карта судьбы (деньги / жар / сдвиг по полю);
   - сразу после покупки карту тянет **партнёр** — фишка не двигается.

### Три уровня смелости

Чем смелее задание, тем меньше плата и тем быстрее растёт жар:

| Уровень | Цена | Жар |
| --- | --- | --- |
| **База** | 100% цены улицы | 0 |
| **Дразнить** | 50% | +1 |
| **Смелее** | 25% | +2 |

```ts
chargeFor(space, tier, mult) = round(price × TIERS[tier].factor × mult / 5) × 5
payoffCost(pending)          = round(chargeFor(space, 'base', mult) × 1.5 / 5) × 5
```

**Откуп** — 150% базовой цены: платите монетами, пропускаете задание, жар не растёт. Если монет не хватает, плата усекается до того, что есть (`transfer` берёт `min(coins, amount)`) — в минус уйти нельзя.

### Сюжет и экономика

- **3 настроения**: Нежность, Флирт, После полуночи. У каждого свой набор заданий на все 17 улиц × 3 уровня и своя колода «сюрпризов». Настроение выбирается один раз и на весь вечер.
- **3 главы**: каждая открывается экраном завязки (фаза `premise`) с новыми **псевдонимами игроков** («Мечтатель / Тихоня» → «Заводила / Хранитель» → «Признательный / Бесстрашный»).
- **Длина вечера**: 4 / 6 / 9 ходов в главе.
- **Финальная глава** — все платы **×2**.
- Старт: **1000** монет каждому.

### Финал: две короны

```
Корона Жадности  → выше netWorth = coins + Σ цен выкупленных улиц
Корона Страсти   → выше heat
```

Один игрок может взять обе — интерфейс так и пишет: «X берёт обе короны».

## 5. Игровой движок

`src/game/engine.ts` — **чистый редьюсер без побочных эффектов**:

```ts
export function reducer(state: GameState, action: Action): GameState
```

Ключевые решения:

- **`structuredClone(state)` в начале каждого действия.** Никаких мутаций входящего состояния: то же самое состояние можно клонировать и пересылать по сети, а React гарантированно видит новый объект.
- **Всё состояние сериализуемо** (`GameState` — только числа, строки, массивы, объекты). Поэтому онлайн — это просто `JSON.stringify` целиком, без дельт и без версионирования сущностей.
- **Действие `sync`** возвращает присланное состояние как есть: так гость принимает истину хоста, не пытаясь смержить.
- **Фаза — часть состояния, а не UI.** Редьюсер отбраковывает действие не той фазы (`if (next.phase !== 'buy') return next`), поэтому «гонка» из двух клиентов не ломает партию: лишние нажатия просто не имеют эффекта.
- **Детерминированный источник случайности для карт**: `rand(state)` — хеш от `state.seed + state.logSeq` (mulberry-подобный перемешивающий блок), а `logSeq` растёт на каждую выдачу. Значит выбор карты судьбы воспроизводим по состоянию, а не по глобальному `Math.random()`. Кубики честно бросает хост (`Math.random`), и результат приезжает гостю внутри состояния.
- **Журнал вечера** — последние 60 записей с тоном (`neutral | money | heat | story`), то есть это часть состояния, и у гостя журнал идентичен хосту.

## 6. 3D-поле

`src/components/three/Board3D.tsx` грузится лениво (`React.lazy`) — three.js не попадает в главный бандл.

- Сцена (`Scene.tsx`): основание поля на `RoundedBox`, 20 плиток, знаки владельцев, две фишки, два кубика, анимация броска и шагов по кольцу (`ringPoint`), `OrbitControls` с ограничением зума.
- **Текстуры печатаются на `canvas`** (`textures.ts`): лица кубиков, шаховая раскраска, вывески улиц. Поэтому перед первым кадром ждём `document.fonts.ready` (с таймаутом 1500 мс) — иначе плитки отрисуются системным шрифтом.
- **Фолбэки**:
  - нет WebGL → то же самое поле на CSS (`Board.tsx`, `board3d--css`);
  - `prefers-reduced-motion: reduce` → фишка не идёт по кольцу, карточка показывается сразу;
  - `Suspense` → скелет `.board3d--skeleton`, пока чанк догружается.
- **Хронометраж хода** (`capabilities.ts`): бросок `1150 мс`, шаг `185 мс`, пауза на прибытии `450 мс`; `walkMs(steps) = steps × 185 + 450`.

Таймеры косметики держит **только хост** (`useMoveTimers`): гость никаких `moving → walking → land` не запускает, он ждёт состояния. У гостя карточка может «подождать», пока фишка дорисует путь (`landAt` + очередь самого свежего состояния в `useGame`).

## 7. Сетевой слой: онлайн без сервера

### Модель: хост авторитетен

```
        хост (players[0])                      гость (players[1])
  useReducer(reducer) ── sendState ──┐   ┌── показывает прилетевшее
        ▲        │                   ▼   ▼
   advance()   intentAllowed ←── sendIntent
```

- **Хост** владеет редьюсером и рассылает **полное состояние** с номером `rev`.
- **Гость** не имеет редьюсера боя: он шлёт **намерения** (`intent`) и отображает состояние хоста.
- Намерение валидируется **на обеих сторонах** одной функцией `intentAllowed(state, actor, action)` (`src/net/protocol.ts`): гость не может ходить за хоста и не трогает фазовые таймеры. Хост проверяет повторно — честный клиент не нужен для корректности, только для комфорта.
- `rev` монотонно растёт у хоста (`sendState` инкрементирует перед отправкой), гость принимает `msg.rev >= rev.current` — старые кадры отбрасываются, порядок не теряется.

### Протокол (`AppMsg`)

| Сообщение | От | Смысл |
| --- | --- | --- |
| `hello {name, wantRev}` | оба, при открытии канала | «я здесь, вот моё имя, дай самое свежее» |
| `hi {name, rev}` | оба в ответ | представление + текущий номер состояния |
| `state {rev, state}` | хост → гость | полный снимок партии |
| `intent {action}` | гость → хост | «хочу сходить»: roll / buy / resolve-tier / pay-off / take-fate / enter-chapter |
| `chat {text}` | оба | переписка, до 200 символов |
| `ping {at}` / `pong {at}` | оба | живость канала и замер задержки в плашке |

Пинг каждые **4 с**; если от партнёра тише **13 с**, плашка показывает «ждём партнёра».

Управляющие сообщения ретранслятора (`SrvMsg`: `join/joined/peer-present/peer-left/full/error`) использует только транспорт `ws`; WebRTC их не видит.

### Три транспорта за одним интерфейсом

`src/net/transport.ts`:

```ts
export interface Transport {
  kind: 'ws' | 'rtc' | 'bc'
  room: string
  send(msg: NetMsg): void
  close(): void
  onMessage: ((msg: NetMsg) => void) | null
  onStatus: ((status: 'connecting' | 'open' | 'closed') => void) | null
}
```

Выбор канала (`transportKind()`):

| Порядок | Канал | Когда |
| --- | --- | --- |
| 1 | `ws` — ретранслятор | задан адрес: `?relay=wss://…` → `localStorage['chmok.relay']` → `VITE_RELAY_URL` |
| 2 | `rtc` — **WebRTC напрямую** | есть `RTCPeerConnection` (нужен HTTPS или `localhost`) |
| 3 | `bc` — BroadcastChannel | браузер без WebRTC: две вкладки одного браузера |

По умолчанию на боевом сайте работает **`rtc`**: сервер не нужен вообще.

### Как устроен WebRTC-канал (`src/net/p2p.ts`)

```ts
const { joinRoom, defaultRelayUrls } = await import('@trystero-p2p/torrent')
joinRoom(
  {
    appId: 'chmok-room',
    relayConfig: { urls: defaultRelayUrls, redundancy: defaultRelayUrls.length },
  },
  code,          // комната = код комнаты
)
```

- **Знакомство** идёт через публичные WebTorrent-трекеры: пиры объявляются на теме, хеш которой Trystero вычисляет из `appId` и кода комнаты, и обмениваются SDP-предложениями. Никакого нашего сервера в этом нет, и никто не видит содержимое хода.
- **Сами ходы** летят по `RTCDataChannel`, зашифрованному DTLS end-to-end — трекер знает только «кто-то ищет этот хеш».
- **STUN**: `stun.l.google.com:19302`, `stun1..3`, `stun.cloudflare.com:3478` (дефолт Trystero). **TURN не используется** — см. ограничения.
- **Канал ровно один.** Принимаем того, кто пришёл первым; если перезагрузившийся гость объявился раньше, чем трекер сообщил об уходе старого, новый пир становится `standby` и занимает канал, как только подаст голос или освободится место. Это спасает от «третьего лишнего» и от залипшего мёртвого пира.
- **Все трекеры сразу** (`redundancy = urls.length`) — из пяти публичных живых обычно три, а выборка «3 из 5» по `appId` может выбросить как раз живые.

### Пул транспортов: почему лобби и игра делят одно соединение

`acquireTransport(room, role, name)` считает владельцев на ключ `` `${room}|${role}` `` и закрывает канал через **5 с** после того, как владельцев не осталось (`PARK_MS`).

```
Лобби хоста (useRoom) ─┐
                       ├─ один и тот же Transport
Игра хоста   (useRoom) ┘
```

Без пула старт главы разрывал пару: лобби размонтировалось, вызывало `leave()`, и гость оставался с мёртвым пиром. Для BroadcastChannel это незаметно, для WebRTC — фатально. Имя игрока в ключ **не входит**: хост переименовывается в лобби, и переименование не должно рвать соединение.

Если новый владелец (экран игры) появляется на уже открытом канале, транспорт проигрывает `onStatus('open')` в `queueMicrotask` — новый владелец сам шлёт `hello`, и хост мгновенно отдаёт актуальное состояние. Отсюда же берётся «ресинк после перезагрузки гостя».

### Что видит игрок

Плашка в шапке партии: `напрямую · Мария на связи · 42 мс`.
Экран ожидания гостя: «Соединяемся с комнатой» / «Ждём первый ход хоста» / «Связи нет — пробуем снова».
В лобби хоста — `linkHint`: «напрямую, без сервера», «через ретранслятор» или «локально: две вкладки».

| **GitHub Actions** | собирает и публикует сайт по push в `main` (`ubuntu-latest`, Node 22) | да | $0 (публичные репозитории) |

| **STUN** (Google / Cloudflare) | определение публичного адреса за NAT | нет | $0 |
| **Google Fonts** | Fredoka + Inter | нет | $0 |
| **Cloudflare Workers + Durable Objects** | *опционально* WebSocket-ретранслятор `ws`, если WebRTC недоступен | да (`wrangler login`) | $0 на Free-тарифе |

Чего здесь **нет**: своего VPS, баз данных, очередей, аккаунтов и логинов, аналитики, рекламных пикселей, CDN-платежей, Sentry и вообще какого-либо бэкенда по умолчанию.

Почему именно так: бесплатный хостинг с постоянным процессом (Render) засыпает через 15 минут и рвёт WebSocket, бесплатного тарифа Fly.io больше нет, Railway — платный триал, Glitch закрыл хостинг приложений в июле 2025. Единственный путь «$0 и без моего сервера» — серверless WebRTC.

## 9. Приватность и данные

- **Ничего не хранится на сервере.** Партия живёт в памяти браузера хоста. Закрыли вкладку — партии нет.
- **По сети летит только** `GameState` (позиции, монеты, жар, владение локациями, журнал, выпавшие задания), имена-псевдонимы и текст переписки.
- **WebRTC-канал зашифрован DTLS** между браузерами; трекер видит лишь хеш комнаты, содержимое он прочитать не может.
- **Ретранслятор `ws` не разбирает сообщения** — Cloudflare Worker пересылает JSON второму сокету той же комнаты и не хранит его (`server/worker.ts`).
- **В браузере хранится два ключа**:

  | Ключ | Что |
  | --- | --- |
  | `chmok.name` | имя игрока, чтобы не вводить заново |
  | `chmok.relay` | адрес ретранслятора, если вы его задали через `?relay=` |

- **Возрастной гейт** (`AgeGate`) стоит на входе в `/play` — игра 18+, контент откровенный, но без порнографии: это задания «на двоих для тех, кто вместе».
- **Третьи стороны, которых замечает ваш браузер**: GitHub (статика), `fonts.googleapis.com` (шрифты), WebTorrent-трекеры и STUN (только во время онлайн-партии).

Нужен Node 18+ (проверено на 22 и 24) и npm.

```bash
npm install

npm run build      # tsc --noEmit && vite build → dist/
npm run preview    # раздать dist локально
npm run typecheck  # только типы

Онлайн-режим локально: `http://localhost` — безопасный контекст, WebRTC работает. Две вкладки (`#/play` → «Создать комнату» и ссылка-приглашение во второй) соединяются напрямую; если браузеру не хватает `RTCPeerConnection`, они договорятся через BroadcastChannel.

Чтобы играть по локальной сети с другого устройства, нужен HTTPS (WebRTC доступен только в безопасном контексте) — или свой ретранслятор, см. [§13](#13-опциональный-ретранслятор-cloudflare).

Пример реального прогона против боевого сайта:

```

guest resynced after reload: true | coins: 1000/1000 1000/1000

coins host page: 1850/1270 | guest page: 1850/1270

## 12. Деплой на GitHub Pages

`.github/workflows/deploy.yml`:

```
push в main (или workflow_dispatch)
  └─ build:  checkout → setup-node 22 (кэш npm) → npm ci →
              npm run build (env VITE_RELAY_URL=${{ vars.RELAY_URL }}) →
              configure-pages → upload-pages-artifact (path: dist)
  └─ deploy: environment github-pages → deploy-pages
```

Что должно быть включено в настройках репозитория (один раз, руками):

1. **Settings → Pages → Build and deployment → Source: GitHub Actions** (не «Deploy from a branch»).
2. Репозиторий **публичный** — на бесплатном тарифе GitHub Pages иначе не работает.
3. Опционально **Settings → Secrets and variables → Actions → Variables → `RELAY_URL`** = `wss://…` — тогда в собранную статику вшьётся адрес ретранслятора, и онлайн пойдёт через `ws` без `?relay=` в ссылке.

Дальше всё просто: `git push origin main` → через ~40 секунд сайт обновлён.

Почему работает в подпапке `/chmok/`: `base: './'` в `vite.config.ts` (все пути относительные) + роутинг по **hash** (`#/play`, `#/rules`) — Pages не знает про SPA-fallback, а hash на сервер не отправляется.

| Chunk Trystero (ленивый, только для онлайна) | 52.84 kB | 18.88 kB |

## 13. Опциональный ретранслятор (Cloudflare)

Нужен, если WebRTC не проходит (жёсткий NAT без TURN, корпоративная сеть, заблокированные трекеры). Один WebSocket-ретранслятор на Worker + Durable Object, бесплатный тариф, комната = один DO, идентификатор выводится из кода комнаты.

```bash
npx --yes wrangler login        # интерактивно, в браузере
npm run dev:relay               # локальный wrangler dev
npm run deploy:relay            # публикация → https://chmok-relay.<ваш>.workers.dev
```

Затем сообщите клиенту адрес — любым из трёх способов:

```
?relay=wss://chmok-relay.<ваш>.workers.dev/ws   (сохранится в localStorage)
localStorage.setItem('chmok.relay', 'wss://…')
RELAY_URL в переменных репозитория → вшьётся в сборку Pages
```

Как устроено (`server/worker.ts`):

- `GET /ws?room=КОД&role=host|guest&name=…` — рукопожатие WebSocket;
- хост всегда один: новое подключение закрывает прежний сокет роли `host`;
- второй гость получает `409 {t:'full'}`;
- `webSocketMessage` — веером второму сокету той же комнаты, содержимое не разбирается;
- сокет **хибернируется** (Durable Objects), простой не стоит денег.

`server/relay.deno.ts` — тот же протокол на Deno для локальной сети; в облаке его быть не должно: разные клиенты могут попасть в разные изоляты, а карта комнат держится в памяти.

## 14. Известные ограничения и troubleshooting

| Симптом | Причина | Что делать |
| --- | --- | --- |
| Долго «Соединяемся с комнатой», потом вдруг работает | Пиры знакомятся через трекеры: announce раз в 10 с | Ждать до ~40 с; не перезагружать обе вкладки одновременно |
| Онлайн не соединяется между устройствами в одной сети/за симметричным NAT | Нет TURN — только host- и srflx-кандидаты | Поднять ретранслятор ([§13](#13-опциональный-ретранслятор-cloudflare)) или добавить `turnConfig` в `joinRoom` |
| На `http://192.168.x.x` работает только «локально: две вкладки» | WebRTC доступен лишь в безопасном контексте | HTTPS (Pages это даёт) или `localhost`, или ретранслятор |
| Один из трекеров умер | Публичные WebTorrent-трекеры живы частично (из RU — три из пяти) | Уже берём все сразу; при массовом отказе — ретранслятор |
| Гость перезагрузил страницу | Новый пир ≠ старый | Штатно: `standby`-перехват + `hello` → хост отдаёт актуальный снимок |
| **Хост** перезагрузил страницу | Состояние редьюсера живёт только у него | Партия начинается заново, это ожидаемо |
| «в комнате уже есть гость» | Двое по одной ссылке | Новый код комнаты; код можно продиктовать голосом |
| Третий игрок по тому же коду молча игнорируется | Канал один, принимаем первого | Это осознанно: код комнаты = приватный приглашающий токен |
| Сборка Pages упала на `npm ci` | `package-lock.json` не закоммичен или не совпал | `npm install` и закоммитить лок-файл |
| Плашка «связь…» не гаснет | Партнёр свернул вкладку | Пинг 4 с, таймаут 13 с — вернётся само |

Прочие границы продукта: ровно два игрока; нет аккаунтов, рейтингов и cloud-сейвов; чат — только текстовый и только внутри партии; контент 18+ и откровенный, но без откровенности в картинках (в игре нет изображений людей, только поле и текст).

## 15. Как расширять

**Добавить локацию.** `src/game/board.ts` — строка в `rows` (`id`, название, цена, глиф), индекс в кольце считается сам. Клеток ровно 20, поэтому новая локация либо заменяет «Сюрприз», либо придётся расширять `ring()` и `layout.ts`.

**Добавить задание.** `src/content/{tender,flirty,late}.ts` — по `spaceId` задаются три строки: `base`, `tease`, `bold`. Нет уровня — сработает дефолт из `taskOf`.

**Новое настроение.** `Mood` в `src/game/types.ts`, колода в `src/content/deck.ts`, три главы в `CHAPTER_MAP` и карты судьбы в `FATE` (`src/game/story.ts`), карточка на лендинге в `MOOD_CARDS`/`MOODS`.

**Новый транспорт.** Реализовать `Transport` (см. `bcTransport` как самый простой образец) и добавить ветку в `transportKind()`/`createTransport()`. Протокол `useRoom` и игра ничего не заметят.

**Менять экономику.** Константы в одном месте: `START_COINS`, `PASS_START`, `HOME_BONUS`, `PAYOFF_FACTOR` (`src/game/story.ts`, `src/game/engine.ts`).
